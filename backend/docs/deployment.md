# Production deployment procedure (AWS ap-south-1)

Status: **documented, validated as code, and rehearsed locally; never executed against AWS.**
There is no AWS account or credential (U-5) and no domain (U-6), so no AWS resource exists.
`prodcheck` refuses a production deployment until real hostnames and an ACME contact are set.
Nothing here makes the system production-ready by itself; see the Phase 3 report for blockers.

## What gets created (Terraform, `deploy/aws/terraform`, one state per environment)

| Area | Resources |
|---|---|
| Network | VPC 10.40.0.0/16, one public subnet (one AZ), IGW, route table, empty default SG, VPC flow logs (REJECT) |
| Firewall | Host SG: in 443/tcp (HTTPS/WSS + ACME TLS-ALPN), in 8883/tcp (MQTT/TLS); out 443/tcp only. No 22/80/1883/5432/2375/8000/8001 |
| Compute | 1 x EC2 Amazon Linux 2023 (t3.medium default), IMDSv2 only (hop limit 1), no SSH key, SSM only, Elastic IP, encrypted root |
| Storage | Separate encrypted gp3 data volume -> `/srv/gossy` (PostgreSQL, broker store, TLS state) |
| Keys | 1 KMS CMK per environment (rotation on): EBS, S3, Secrets Manager, CloudWatch Logs, SNS |
| Registry | ECR `gossy/<env>/backend` - immutable tags, scan on push, KMS, keep 30 |
| Secrets | Secrets Manager `gossy/<env>/runtime` - generated by Terraform as ephemeral values, written write-only (never in state) |
| Settings | SSM parameter `/gossy/<env>/host-env` - NON-secret host settings (`/etc/gossy/gossy.env`), refreshed on every deployment |
| Backups | S3 `gossy-<env>-backups-<account>` (SSE-KMS, versioned, TLS-only, public access blocked, lifecycle retention) |
| Artifacts | S3 `gossy-<env>-artifacts-<account>` (deploy bundles) |
| Monitoring | Log groups (KMS, retention), SNS alarm topic (KMS), 16 alarms (see `monitoring.tf`) |
| IAM | Host role scoped to this environment's repo, secret, settings parameter, bucket prefixes, log groups, `Gossy*` metric namespaces |

## Validate the infrastructure code (no AWS account needed)

```bash
cd backend/deploy/aws/terraform
terraform fmt -check -recursive .. && terraform init -backend=false && terraform validate
terraform test -var-file=environments/staging.tfvars      # policy tests, AWS provider mocked
terraform test -var-file=environments/production.tfvars
```

`terraform plan` against the real account is the first step that needs credentials.

## One-time per AWS account

```bash
cd backend/deploy/aws/bootstrap
terraform init && terraform apply           # S3 state bucket (versioned, encrypted, TLS-only)
```

## Per environment (staging first, then production)

```bash
cd backend/deploy/aws/terraform
cp environments/staging.backend.hcl.example environments/staging.backend.hcl   # fill bucket name
terraform init -backend-config=environments/staging.backend.hcl
# docker_compose_sha256: from the release's checksums file (pinned host download)
terraform apply -var-file=environments/staging.tfvars -var docker_compose_sha256=<sha256>
```

1. **Image** - build once, push with an immutable tag (never `latest`):
   ```bash
   TAG=0.3.0-$(date -u +%Y%m%d%H%M)
   docker build --target runtime -t "$REPO:$TAG" backend/
   aws ecr get-login-password --region ap-south-1 | docker login --username AWS --password-stdin "${REPO%%/*}"
   docker push "$REPO:$TAG"      # scan on push; check findings before deploying
   ```
   Promotion to production = copy the same digest to the production repository.
2. **Deploy bundle** - `tar -C backend/deploy/prod -czf bundle-$TAG.tar.gz --exclude rehearsal .`,
   upload to `s3://<artifacts>/bundles/`, then either set `deploy_bundle_key` before the first
   apply (first boot installs it) or, on an existing host (SSM): download, extract, `bash install.sh`.
3. **DNS (U-6)** - create A records for the API and MQTT hostnames -> `terraform output elastic_ip`.
   Set `api_public_host`, `mqtt_public_host`, `acme_email` in the tfvars and `terraform apply`:
   this updates the SSM parameter `/gossy/<env>/host-env`. The host copies it to
   `/etc/gossy/gossy.env` at the start of the next `deploy.sh` (EC2 user-data runs only on the
   first boot, so settings are deliberately not delivered through it).
4. **Deploy** - SSM Run Command on the instance: `/opt/gossy/bin/deploy.sh <TAG>`. It refreshes the
   settings, renders secrets (tmpfs), logs in to ECR, pulls, runs `gossy.prodcheck` (refuses unsafe
   config), starts the database, reconciles role passwords, runs migrations, starts API + Caddy,
   waits for the MQTT certificate, starts Mosquitto + ingest, and checks readiness.
5. **Verify from outside** - `https://<api-host>/healthz` = 200; `/readyz`, `/metrics`, `/docs` = 404;
   `openssl s_client -connect <mqtt-host>:8883 -servername <mqtt-host> -verify_return_error`;
   ports 22/80/1883/5432/8000/8001 closed. Run `tests/integration/test_edge.py` with
   `GOSSY_TEST_EDGE_*` pointing at the host (public CA: leave `GOSSY_TEST_EDGE_CA_FILE` unset).
6. **Monitoring** - `python deploy/aws/check-monitoring.py ingest.txt api.txt` (alarms vs agent vs
   exported metrics), then confirm in CloudWatch that `Gossy/App` and `Gossy/Host` receive data,
   subscribe a mailbox to the alarm topic (`alarm_email`), and trigger one alarm on staging.
7. **Admin** - grant the admin role with the operator CLI only (admin authentication design is
   DECISION NEEDED): `docker compose ... exec api python -m gossy.manage set-role --phone <E.164> --role admin`.

## First deployment to AWS: what still has to be verified there

The local rehearsal cannot exercise these; treat each as unverified until done on staging:
`terraform plan/apply`, EC2 user-data (packages, data-volume format/mount, chrony), IAM
permissions as actually enforced, security group behaviour, ECR push/pull and scan, Secrets
Manager and SSM parameter reads, S3 backup upload/download with SSE-KMS and lifecycle expiry,
Let's Encrypt issuance and renewal, systemd units and timers (including reboot order), the
CloudWatch agent (metrics, EMF conversion of counters), the `awslogs` log driver, alarm
evaluation and SNS delivery.

## Operations

| Task | How |
|---|---|
| Upgrade | build + push new tag, `deploy.sh <new tag>` (migrations run first; data untouched) |
| Rollback | `deploy.sh <previous tag>` - only if no migration was applied in between; otherwise restore |
| Settings change | edit tfvars, `terraform apply` (updates the SSM parameter), `deploy.sh <tag>` |
| Secret rotation | increment `secret_version`, `terraform apply`, then `deploy.sh <tag>` (re-renders, reconciles DB role passwords, recreates the containers holding credentials). Invalidates all sessions and changes MQTT service passwords |
| Backup | daily 21:00 UTC (`gossy-backup.timer`) -> S3 SSE-KMS; manual: `/opt/gossy/bin/backup.sh` |
| Restore | new host / empty data volume: `/opt/gossy/bin/restore.sh s3://.../gossy-<env>-<stamp>.dump <TAG>`. Verifies the checksum, refuses a non-empty database without changing anything |
| Certificates | Caddy renews automatically; `gossy-cert-sync.timer` copies the MQTT certificate daily and restarts the broker only if it changed |
| Logs | CloudWatch `/gossy/<env>/app` (one stream per container), ops scripts in the same group (`ops-*`) |
| Shell | `aws ssm start-session --target <instance-id>` (no SSH) |
| Host replacement | `terraform apply -replace=aws_instance.host` (production: lift termination protection first): the data volume and Elastic IP are re-attached; user-data bootstraps the new host; then `deploy.sh <tag>`. Not rehearsed |

## Local rehearsal (no AWS)

`deploy/prod/rehearsal/` runs the same bundle, env file layout, secret document and scripts on a
clean Docker-in-Docker "host". Substitutions: docker save/load for ECR, a local JSON secret
document for Secrets Manager, a Docker volume for S3, Caddy's internal CA with `*.invalid` names for
Let's Encrypt, json-file logs for CloudWatch. No systemd and no CloudWatch agent run there.

```bash
cd backend
TAG=0.3.0-rehearsal.$(date -u +%Y%m%d%H%M)
docker build --target runtime -t gossy-backend:$TAG . && docker build --target dev -t gossy-backend:dev .
bash deploy/prod/rehearsal/run-rehearsal.sh up gossy-rehearsal-host 28443 28883 $TAG
bash deploy/prod/rehearsal/run-rehearsal.sh exec gossy-rehearsal-host 'bash /opt/gossy/rehearsal/alert-walkthrough.sh'
bash deploy/prod/rehearsal/run-rehearsal.sh exec gossy-rehearsal-host 'bash /opt/gossy/rehearsal/queue-overflow.sh'
bash deploy/prod/rehearsal/run-rehearsal.sh down gossy-rehearsal-host
```

See the Phase 3 report for the results and for what the rehearsal does not prove.
